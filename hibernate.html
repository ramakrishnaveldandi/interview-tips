Core concepts

In Spring you inject EntityManager; unwrap with em.unwrap(Session.class) for Hibernate-specific APIs.

get() vs load() — and their modern equivalents?
  • get() / find() — queries immediately, returns null if not found.
  • load() / getReference() — returns an uninitialized proxy without a query; throws ObjectNotFoundException / EntityNotFoundException on first access if the row doesn't exist.
Session.load() is deprecated in Hibernate 6 — use getReference(). Likewise get() → find().

How does dirty checking work? What are flush modes?

When an entity is loaded, Hibernate stores a snapshot of its state. On flush it compares current values with the snapshot and issues UPDATEs for changed entities — no explicit save needed.

Flush modes: AUTO (default — flush before commit and before queries that touch dirty tables), COMMIT (only at commit), ALWAYS (before every query), MANUAL (only on flush(); used by read-only transactions).

@Transactional(readOnly = true) sets flush mode to MANUAL and lets Hibernate skip snapshots — a real performance gain for read paths.
What are Hibernate proxies and when do they cause problems?

For lazy @ManyToOne / getReference(), Hibernate returns a generated subclass (via ByteBuddy) that loads data on first method call. Pitfalls:

  • getClass() returns the proxy class — use Hibernate.getClass(obj) or instanceof.
  • final classes/methods can't be proxied → association becomes eager.
  • Accessing a proxy after the session closes → LazyInitializationException.
  • Polymorphic proxies: a proxy of Payment is not an instanceof CardPayment — use Hibernate.unproxy().

How do you configure the second-level cache with JCache/Ehcache?

Concurrency strategies: READ_ONLY (immutable data), NONSTRICT_READ_WRITE, READ_WRITE (soft locks), TRANSACTIONAL (JTA).

Fetching & the N+1 problem

What is the N+1 select problem? How do you detect it?

One query loads N parents, then accessing a lazy association on each fires N more queries.

Detect: enable SQL logging, Hibernate statistics, or assert query counts in tests (e.g. with datasource-proxy or Hypersistence Utils' SQLStatementCountValidator).

What are the ways to fix N+1?
Don't combine JOIN FETCH on a collection with pagination — Hibernate paginates in memory and logs HHH90003004. Page the parent ids first, then fetch.
What causes MultipleBagFetchException and how do you fix it?

Hibernate can't JOIN FETCH two or more List ("bag") collections at once — the cartesian product makes duplicates indistinguishable.

  • Fetch one collection per query (two queries in the same transaction — the context merges results).
  • Change collections to Set (works, but still a cartesian product — watch row counts).
  • Use @BatchSize / default_batch_fetch_size for the second collection.
  • Use @OrderColumn to turn a bag into an indexed list.
What is LazyInitializationException? Should you enable Open Session in View?

It's thrown when a lazy association is accessed after the session is closed — e.g. in a controller or during JSON serialization.

Spring Boot enables Open Session in View (spring.jpa.open-in-view=true) by default and logs a warning. It keeps the session open during view rendering, hiding the exception but causing hidden queries outside transactions and holding DB connections longer.

Better fixes: fetch what you need inside the service transaction (JOIN FETCH / entity graph), return DTOs instead of entities, or call Hibernate.initialize() deliberately. Avoid hibernate.enable_lazy_load_no_trans — it's an anti-pattern.

Performance tuning

How do you enable JDBC batching? Why doesn't it work with IDENTITY?

With IDENTITY the id is known only after the INSERT executes, and Hibernate must put the entity in the persistence context with its id immediately — so it executes each insert right away and silently disables insert batching. Use SEQUENCE with a pooled optimizer (allocationSize).

For PostgreSQL also add reWriteBatchedInserts=true to the JDBC URL.

What does @DynamicUpdate do? When is it useful?

By default Hibernate's UPDATE includes all columns (a statement it can cache and batch). @DynamicUpdate generates SQL with only the changed columns.

  • ✅ Useful for wide tables, reducing lock contention / triggers on unchanged columns, and with optimistic locking OptimisticLockType.DIRTY.
  • ❌ SQL generated per update — less statement caching and batching.
What is a StatelessSession?

A lightweight session with no persistence context: no first-level cache, no dirty checking, no cascades, no lazy loading. Each operation executes SQL directly — ideal for bulk imports/exports and ETL.

Hibernate 6.3+ also adds insertMultiple()/upsert(), and stateless sessions are central to Hibernate 7's Jakarta Data repositories.

How do you log SQL and see Hibernate statistics?
Prefer logger configuration over spring.jpa.show-sql=true — show-sql writes to stdout and bypasses your logging framework.

Modern Hibernate & best practices

What changed in Hibernate 6 and 7?
  • Jakarta namespace: javax.persistence → jakarta.persistence (6.0); JPA 3.1 in 6.x, JPA 3.2 in 7.
  • SQM (Semantic Query Model): a new HQL/Criteria parser — HQL now supports set operations (union), window functions, CTEs, filter clauses and more.
  • Read-by-position JDBC result handling → faster result processing.
  • Better type system: @JdbcTypeCode(SqlTypes.JSON) for JSON columns, native UUID, Instant/OffsetDateTime handling.
  • Default AUTO id generation uses sequences; hibernate_sequence replaced by per-entity sequences.
  • Hibernate 7 (2025): Java 17 baseline, legacy Session methods removed, Jakarta Data support, Apache License 2.0.
How should you implement equals() and hashCode() for entities?

Requirements: consistent across all lifecycle states (transient → managed → detached) and work with proxies. Options:

  • Natural/business key (e.g. ISBN, email) annotated @NaturalId — best when one exists.
  • Generated id with a constant hashCode() — so an entity in a HashSet before persist isn't lost after the id is assigned.
Never use Lombok's @Data / @EqualsAndHashCode on entities — it includes lazy collections (triggering loads or stack overflows on bidirectional links) and mutable fields.
