Core

What is Spring Boot and how is it different from the Spring Framework?

Spring Framework provides the core (IoC container, AOP, MVC, transactions, data access). Spring Boot is an opinionated layer on top that removes boilerplate:

  • Auto-configuration — configures beans based on the classpath and properties.
  • Starters — curated dependency sets with compatible versions.
  • Embedded server — Tomcat/Jetty/Undertow inside an executable "fat" JAR; no WAR deployment needed.
  • Production features — Actuator, metrics, health checks, externalized configuration.
One-liner: Spring is the engine; Spring Boot is the car that's ready to drive.
What does @SpringBootApplication do?

It is a meta-annotation combining three annotations:

  • @SpringBootConfiguration — a specialised @Configuration.
  • @EnableAutoConfiguration — loads auto-configuration classes listed in META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports.
  • @ComponentScan — scans the package of the annotated class and sub-packages.
Put the main class in a root package — beans outside its package tree are not scanned.
How does auto-configuration work? Explain @Conditional annotations.

Each auto-configuration class is a @AutoConfiguration guarded by conditions. Beans are created only when conditions match, and your own beans take precedence (@ConditionalOnMissingBean).

Common conditions: @ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnBean, @ConditionalOnProperty, @ConditionalOnWebApplication. Run with --debug or hit /actuator/conditions to see the condition evaluation report.

What are starters? Name a few.

Starters are dependency descriptors that pull in everything needed for a capability, with versions managed by the Boot BOM (spring-boot-dependencies).

  • spring-boot-starter-web — Spring MVC + Jackson + embedded Tomcat
  • spring-boot-starter-webflux — reactive stack on Netty
  • spring-boot-starter-data-jpa — Hibernate + Spring Data JPA + HikariCP
  • spring-boot-starter-security, spring-boot-starter-oauth2-resource-server
  • spring-boot-starter-actuator, spring-boot-starter-validation, spring-boot-starter-test

DI & Beans

What is IoC and Dependency Injection? Why prefer constructor injection?

Inversion of Control: the container, not your code, creates and wires objects. DI is how it supplies dependencies. Constructor injection is preferred because:

  • Dependencies can be final → immutable, thread-safe.
  • Object is never in a half-initialised state; missing deps fail at startup.
  • Easy to unit test without Spring (new OrderService(mockRepo)).
  • Too many constructor parameters makes a design smell visible.

Injecting a prototype into a singleton gives you only one instance. Use ObjectProvider<T>, @Lookup, or a scoped proxy to get a fresh one each time.
Explain the bean lifecycle.
  1. Instantiate (constructor) → inject dependencies.
  2. *Aware callbacks (BeanNameAware, ApplicationContextAware).
  3. BeanPostProcessor.postProcessBeforeInitialization.
  4. @PostConstruct → InitializingBean.afterPropertiesSet() → custom initMethod.
  5. BeanPostProcessor.postProcessAfterInitialization (AOP proxies are created here).
  6. Bean in use… then on shutdown: @PreDestroy → DisposableBean.destroy() → destroyMethod.
@Component vs @Bean — when to use which?
  • @Component (and @Service, @Repository, @Controller) — on your own classes, discovered by component scanning.
  • @Bean — on a factory method in a @Configuration class; use for third-party classes you can't annotate, or when creation needs logic.

@Repository also enables exception translation into Spring's DataAccessException hierarchy.

Two beans of the same type exist. How do you resolve the ambiguity?

@Qualifier beats @Primary. Without either, startup fails with NoUniqueBeanDefinitionException.

How does Spring handle circular dependencies?

Since Spring Boot 2.6 circular references are prohibited by default and startup fails with BeanCurrentlyInCreationException. With constructor injection, they can never be resolved. Fixes, best first:

  1. Redesign — extract the shared logic into a third bean, or use events (ApplicationEventPublisher).
  2. Inject lazily: @Lazy on the constructor parameter or ObjectProvider<T>.
  3. Last resort: spring.main.allow-circular-references=true (only works with setter/field injection).

Configuration

How do profiles work? Show an application.yml example.

Activate with --spring.profiles.active=prod or SPRING_PROFILES_ACTIVE=prod. Profile-specific files application-prod.yml also work. Beans can be limited with @Profile("!prod").

How do you bind type-safe configuration with @ConfigurationProperties?
Prefer this over many @Value annotations: it's validated, grouped, immutable and IDE-autocompleted (with spring-boot-configuration-processor).
What is the order of precedence for externalized configuration?

Later sources override earlier ones. Simplified, from lowest to highest:

  1. Default properties (SpringApplication.setDefaultProperties)
  2. application.yml/properties inside the JAR
  3. Profile-specific application-{profile}.yml inside the JAR
  4. application.yml outside the JAR (e.g. ./config/)
  5. Profile-specific files outside the JAR
  6. OS environment variables (SERVER_PORT)
  7. Java system properties (-Dserver.port)
  8. Command-line arguments (--server.port=9090) — highest

spring.config.import can pull in extra sources such as configserver:, Vault or Kubernetes ConfigMaps.

Data & Transactions

Explain @Transactional propagation and isolation.
PropagationBehaviour
REQUIRED (default)Join existing transaction or start a new one
REQUIRES_NEWSuspend current, always start a new one (e.g. audit log that must persist even on rollback)
NESTEDSavepoint inside current transaction
SUPPORTSJoin if present, otherwise run non-transactionally
MANDATORYMust be called inside a transaction, else exception
NOT_SUPPORTED / NEVERSuspend / fail if a transaction exists

Isolation (READ_COMMITTED, REPEATABLE_READ, SERIALIZABLE…) defaults to the database's level. Use readOnly = true on queries — Hibernate skips dirty checking.

Why does @Transactional sometimes not work? (self-invocation)

@Transactional is applied via an AOP proxy. Calls that don't go through the proxy aren't intercepted:

  • Self-invocation — this.save() from another method in the same class.
  • Method is private or final (CGLIB can't override it).
  • Bean not managed by Spring (created with new).
  • Exception is caught and swallowed inside the method.
What are the default rollback rules?

By default Spring rolls back on unchecked exceptions (RuntimeException, Error) and commits on checked exceptions.

Production readiness

What is Spring Boot Actuator? Which endpoints are most useful?

Actuator exposes operational endpoints: /actuator/health (with Kubernetes liveness/readiness groups), /info, /metrics, /prometheus, /env, /loggers (change log levels at runtime), /threaddump, /heapdump, /conditions, /beans, /mappings.

Only health is exposed over HTTP by default. Never expose env or heapdump publicly — secure them with Spring Security.
How do you add observability (metrics & tracing)?

Spring Boot 3 uses Micrometer for metrics and Micrometer Tracing (replacing Spring Cloud Sleuth) with OpenTelemetry or Brave bridges. The Observation API produces both metrics and spans from one instrumentation.

Or simply annotate with @Observed / @Timed. Trace IDs are added to logs automatically.

What is a GraalVM native image and what are its trade-offs?

Spring AOT processing generates bean definitions at build time, then GraalVM compiles the app ahead-of-time to a native executable.

  • ✅ Startup in tens of milliseconds, much lower memory — ideal for serverless and scale-to-zero.
  • ❌ Long build times, closed-world assumption (reflection/proxies need hints via RuntimeHints), no runtime profile switching of @Profile beans, lower peak throughput without PGO.

Microservices

Which Spring Cloud components are used in a typical microservices setup?
  • Spring Cloud Gateway — API gateway: routing, rate limiting, auth token relay.
  • Spring Cloud Config Server — centralised, Git-backed configuration; clients use spring.config.import=configserver:.
  • Service discovery — Eureka / Consul, or Kubernetes DNS services (often no registry needed on K8s).
  • Load balancing — Spring Cloud LoadBalancer (@LoadBalanced client builders).
  • Resilience4j — circuit breaker, retry, rate limiter, bulkhead.
How does a circuit breaker work? Show Resilience4j usage.

States: CLOSED (calls flow, failures counted) → OPEN when failure rate exceeds threshold (calls fail fast to a fallback) → after a wait, HALF_OPEN lets trial calls through and closes again if they succeed.
