What are the requirements for a class to be an entity?
  • Annotated with @Entity and has a primary key (@Id or @EmbeddedId).
  • A public or protected no-arg constructor.
  • Class must not be final, and persistent methods/fields not final (needed for lazy proxies).
  • Top-level class (not an enum, interface or record).

What are the entity lifecycle states?
  • New / Transient — created with new, not associated with a persistence context.
  • Managed / Persistent — tracked by the persistence context; changes are flushed automatically (dirty checking).
  • Detached — was managed, but the context was closed/cleared; changes are not tracked.
  • Removed — scheduled for deletion on flush.
What is the persistence context (first-level cache)?

The persistence context is the set of managed entity instances for an EntityManager — typically scoped to one transaction in Spring. It guarantees:

  • Identity — within one context, the same row is always the same Java object.
  • Caching — repeated find() for the same id hits memory, not the DB.
  • Write-behind — SQL is batched and executed on flush/commit.
  • Dirty checking — modified managed entities are updated automatically.
Loading thousands of entities in one transaction bloats the context. In batch jobs call em.flush(); em.clear(); periodically.
Explain persist, merge, remove, find and getReference.
  • persist(e) — makes a new entity managed; returns void. Throws if detached.
  • merge(e) — copies state of a detached entity onto a managed instance and returns it. Use the returned object.
  • remove(e) — marks a managed entity for deletion.
  • find(Class, id) — hits the DB immediately (or cache); returns null if not found.
  • getReference(Class, id) — returns a lazy proxy without a query; throws EntityNotFoundException on first access if missing. Great for setting foreign keys.

Relationships

Explain owning side and mappedBy in a bidirectional @OneToMany.

The owning side holds the foreign key and controls the DB column — in one-to-many it is always the @ManyToOne side. The inverse side declares mappedBy and is ignored for writes, so keep both sides in sync with helper methods.

A unidirectional @OneToMany without @JoinColumn creates an extra join table — usually not what you want.
How do you map @ManyToMany? When should you use an explicit join entity?

As soon as the link needs its own data (enrolled date, grade), replace it with an entity Enrollment having two @ManyToOnes. Never use CascadeType.REMOVE on many-to-many.

What cascade types exist? What's the difference between CascadeType.REMOVE and orphanRemoval?

Cascade types: PERSIST, MERGE, REMOVE, REFRESH, DETACH, ALL. They propagate an EntityManager operation from parent to children.

  • REMOVE — deletes children when the parent is deleted.
  • orphanRemoval = true — additionally deletes a child when it is removed from the collection (dereferenced).
Cascade only from aggregate root to its owned parts (Order → OrderLines). Never cascade from child to parent.

EAGER can't be turned off per query and causes extra selects (N+1) everywhere. Set fetch = FetchType.LAZY on all to-one associations and fetch what you need per use case with JOIN FETCH or @EntityGraph.

Queries

JPQL vs Criteria API vs native SQL — when to use each?
  • JPQL — object-oriented, portable, queries entities and fields. Default choice.
  • Criteria API — type-safe, programmatic; good for dynamic filters (or use Specifications / Querydsl).
  • Native SQL — DB-specific features (window functions, CTEs, JSON operators, hints).
What are Spring Data derived query methods? Show @Query and @Modifying.
Bulk @Modifying queries skip lifecycle callbacks, @Version checks and cascades, and leave the context stale — hence clearAutomatically = true.
What are projections? Compare interface and DTO (record) projections.

Projections fetch only the columns you need instead of full managed entities — faster and no dirty checking overhead.

How do pagination and sorting work in Spring Data?

In controllers, accept Pageable directly: GET /employees?page=0&size=20&sort=name,asc. For very large tables prefer keyset (seek) pagination — Spring Data 3.1+ supports ScrollPosition / Window<T>.

Locking, auditing & advanced mapping

Optimistic vs pessimistic locking — how and when?

Optimistic: add a @Version column. Every UPDATE includes where version = ?; if 0 rows change, JPA throws OptimisticLockException (Spring: ObjectOptimisticLockingFailureException). Best when conflicts are rare — no DB locks held.

Pessimistic: takes a DB row lock (SELECT … FOR UPDATE). Use when conflicts are frequent and retrying is expensive (seat booking, inventory).

How do you implement auditing (created/modified by & date)?

For full change history (who changed what), use Hibernate Envers (@Audited).

What are @Embeddable types and composite keys?

An @Embeddable is a value object without its own identity whose fields are stored in the owning entity's table. Since JPA 3.2 (Jakarta EE 11) / Hibernate 6.2+, a record can be an embeddable.
