OOP & basics

What is the contract between equals() and hashCode()?
  • If a.equals(b) is true, then a.hashCode() == b.hashCode() must be true.
  • Equal hash codes do not imply equality (collisions are allowed).
  • equals must be reflexive, symmetric, transitive, consistent, and x.equals(null) is false.

Overriding equals without hashCode breaks HashMap/HashSet: two "equal" keys land in different buckets.

Use fields that never change in hashCode(). Mutating a key after inserting it into a HashMap makes it unreachable.
Why is String immutable, and what is the String pool?

The String pool (in the heap since Java 7) stores one copy of each literal. Immutability makes that sharing safe and also gives:

  • Security — class names, file paths, URLs and DB credentials cannot be changed after validation.
  • Thread safety — no synchronization needed.
  • Cached hash code — ideal as HashMap keys.
Use StringBuilder for concatenation in loops; it is mutable and not synchronized (StringBuffer is the synchronized legacy version).
What is the difference between == and equals()?

== compares references for objects (and values for primitives). equals() compares logical content as defined by the class — Object.equals defaults to ==.

Explain final, finally and finalize().
  • final — keyword: a final variable cannot be reassigned, a final method cannot be overridden, a final class cannot be extended.
  • finally — block that always runs after try/catch (unless the JVM exits), used for cleanup.
  • finalize() — Object method called by GC before reclaiming; unpredictable, deprecated since Java 9 and deprecated for removal since 18 (JEP 421). Use try-with-resources or java.lang.ref.Cleaner.

Is Java pass-by-value or pass-by-reference?

Always pass-by-value. For objects, the value passed is a copy of the reference. You can mutate the object through it, but reassigning the parameter does not affect the caller.

Collections

How does HashMap work internally?
  1. Backed by an array of buckets (Node[] table), default capacity 16, load factor 0.75.
  2. put(k, v): compute hash = h ^ (h >>> 16), index = (n - 1) & hash.
  3. Empty bucket → insert node. Otherwise walk the chain: if a key is equals(), replace the value; else append.
  4. Treeification (Java 8): when a bucket holds more than 8 nodes and capacity ≥ 64, the list becomes a red-black tree (O(log n) lookups). It reverts to a list below 6.
  5. When size > capacity × loadFactor the table doubles and entries are redistributed (each node stays at index i or moves to i + oldCap).

Allows one null key (bucket 0) and many null values. Not thread-safe.

If you know the size, pre-size it: HashMap.newHashMap(1000) (Java 19+) or new HashMap<>(1334).
How is ConcurrentHashMap thread-safe without locking the whole map?

Since Java 8 it uses CAS to insert into empty buckets and synchronized on the first node of a bucket otherwise, so threads writing to different buckets never block each other. Reads are lock-free (volatile reads). Resizing is done cooperatively by multiple threads.

  • Does not allow null keys or values (ambiguity between "absent" and "null").

What are fail-fast and fail-safe iterators?

Fail-fast iterators (ArrayList, HashMap) check a modCount and throw ConcurrentModificationException if the collection is structurally modified during iteration (except via iterator.remove()). Fail-safe / weakly consistent iterators (CopyOnWriteArrayList, ConcurrentHashMap) work on a snapshot or tolerate concurrent changes.

Comparable vs Comparator?

Comparable.compareTo defines the natural ordering inside the class (one ordering). Comparator is an external strategy — you can define many.

Exceptions

Checked vs unchecked exceptions?
  • Checked (subclasses of Exception but not RuntimeException): must be caught or declared — e.g. IOException, SQLException. Represent recoverable conditions.
  • Unchecked (RuntimeException and Error): programming bugs or unrecoverable states — NullPointerException, IllegalArgumentException, OutOfMemoryError.

Spring favors unchecked exceptions (e.g. it translates SQLException into DataAccessException), and @Transactional rolls back on unchecked exceptions by default.

How does try-with-resources work? What are suppressed exceptions?

Any AutoCloseable declared in the header is closed automatically in reverse order. If both the body and close() throw, the body's exception is thrown and the close exception is attached via getSuppressed().

Java 8 essentials

What is a functional interface? Name the core ones.

An interface with exactly one abstract method (optionally annotated @FunctionalInterface), so it can be the target of a lambda or method reference.

Lambdas can capture only effectively final local variables.

Explain map vs flatMap and groupingBy with examples.

map transforms each element 1→1; flatMap maps each element to a stream and flattens the result 1→N.

Streams are lazy: intermediate operations run only when a terminal operation (collect, forEach, findFirst) is invoked, and a stream can be consumed only once.
How should Optional be used (and not used)?

Use Optional as a return type to signal "may be absent". Avoid it for fields, method parameters or collections, and never call get() without checking.

Why is java.time better than Date/Calendar?

It is immutable and thread-safe, has clear types (LocalDate, LocalDateTime, ZonedDateTime, Instant, Duration, Period), and months are 1-based.

Store Instant / UTC in the database; convert to a zone only for display.
How do you compose async calls with CompletableFuture?

thenApply = map, thenCompose = flatMap, thenCombine = zip two futures. Always pass your own executor for blocking I/O — the default is the common ForkJoinPool.

What does volatile guarantee — and what doesn't it?

volatile guarantees visibility (writes go to main memory and establish happens-before) and prevents reordering around the access. It does not make compound operations like count++ atomic — use AtomicInteger/LongAdder or a lock.

How do you use ExecutorService correctly?

Avoid Executors.newCachedThreadPool() / unbounded queues under load. Size CPU-bound pools ≈ number of cores; I/O-bound pools larger (or use virtual threads on Java 21+).

What is a deadlock and how do you prevent it?

Two or more threads wait forever for locks held by each other. Required conditions: mutual exclusion, hold-and-wait, no preemption, circular wait.

Other techniques: tryLock with timeout, minimise lock scope, prefer higher-level concurrency utilities. Detect with jstack <pid> ("Found one Java-level deadlock").

JVM internals

Describe the JVM memory areas.
  • Heap — all objects; shared; managed by GC (young gen: Eden + survivors, old gen).
  • Metaspace (Java 8+, replaced PermGen) — class metadata in native memory.
  • Stack — one per thread: frames with local variables and partial results. Overflow → StackOverflowError.
  • PC register and native method stack — per thread.
  • Code cache — JIT-compiled native code.
How does class loading work? What is the parent delegation model?

Phases: Loading → Linking (verify, prepare, resolve) → Initialization (static initializers run on first active use).

Loaders: Bootstrap (core java.base) → Platform → Application/System (classpath). A loader first delegates to its parent and only loads the class itself if the parent cannot, which prevents user code from replacing java.lang.String. Application servers and Spring Boot's fat-jar loader add custom loaders.

How does garbage collection work at a high level?

GC finds objects unreachable from GC roots (stack locals, static fields, JNI refs, active threads) and reclaims them. The generational hypothesis — most objects die young — means new objects go to Eden; survivors are copied between survivor spaces and promoted to the old generation after several cycles.

  • Minor GC — young gen, frequent and fast.
  • Major/Full GC — old gen / whole heap, expensive.
  • Collectors: Serial, Parallel, G1 (default since Java 9), ZGC, Shenandoah.
Memory leaks in Java are objects that are still reachable but no longer needed — e.g. growing static maps, unremoved listeners, ThreadLocals in pooled threads.
